## 2. Pipeline/port joint fix (the reported grid bug)

Three root causes were found and fixed:

1. **Connector direction.** `_add_pipe_connectors` walked from the pipe to the
   building but tested the building's port with the *forward* side. The solver
   walks building → pipe, so the port check must use `-d`. The same convention
   is now used by `_pipe_mask`, `_port_joint_at`, `_adjacent_port_pad`, and the
   connector.
2. **2×2 scaling.** `_try_build`/`_restore_building` passed the default 1-cell
   fit to `_spawn_model`, so a refinery was 15 m wide on a 32 m block. They now
   fit to `footprint × CELL × BUILDING_FIT` (31.4 m for 2×2).
3. **Joint geometry.** Connectors now start at the pipe tile edge and end at
   the structure's **actual silhouette** (`_structure_half`), not a fixed 7 m
   stub. `_lay_line` lifts the corridor to the highest pad it plugs into and a
   wall riser absorbs any step.

Evidence: `docs/img/game_joint.png` (pipe entering a pumpjack), the port overlay
(`game_pipe_ports.png`), and the suite checks:

```
PASS  motor side has no pipe arm
PASS  pipe on a port side grows a joint arm
PASS  pipe joint reaches the structure surface
PASS  pipe run is lifted to the structure pad
PASS  2x2 pipe joints use the block's real face
PASS  pipe laid before a structure grows its joint arm
PASS  bulldozing a structure removes the joint arm
```

## 5. Data-driven catalogue

`res://data/catalogue.tres` holds **29 entries** (24 structures + 4 fleet units
+ the Truck Depot). Each entry is a `BuildingDefinition` with role, ports,
capacity, UI data, icon path, placement flags and role-specific capacity. The
menu, hotkeys, icons, models, placement and simulation all read the catalogue,
so a new structure is data + a model + `assets/icons/<id>.png`.

Role behaviours: `producer`, `buffer`, `consumer`, `booster`, `processor`,
`meter`, `survey`, `transport`, `access`, `unit`.
